LOOP has two complementary interfaces: this guide explains the common tasks in plain language, while the interactive API reference lists every request field and response schema.

1

Create a key

Approved users create a scoped key in the API Keys tab. Copy it once and store it as a secret.

2

Choose a scope

Start with data:read. Add write scopes only when your integration needs them.

3

Make a request

Use the API base URL below and send your key in the X-API-Key header.

Make your first API request

List materials matching a composition and structure family. Replace the placeholder with a key from the API Keys page.

curl --request GET \
  "{{ materials_url }}?elements=Ti,Zr,O&structure_family=fluorite" \
  --header "X-API-Key: $LOOP_API_KEY"

A successful response has a data array and pagination metadata. Try the same request in Swagger before using it in a script.

Authentication and scopes

Use a separate, named key for each notebook, script, or service. LOOP stores only a hash of the secret; you can revoke a key at any time.

ScopeUse it for
data:readReading materials and individual records.
data:writeCreating, updating, or deleting experimental, literature, and computational records.
files:writeAdding an XRD CSV alongside an experimental record.
imports:writeValidating or committing JSON and JSONL batch imports.
Keep keys private. Use environment variables or your organization’s secret manager. Never paste a real key into source control, shared notebooks, or an LLM prompt.

Materials-data workflows

Use the workflow that matches the information you have. The API uses the same validation and persistence paths as LOOP’s Add Data forms.

Experimental synthesis and XRD

Send an ordered synthesis_steps array to POST /experiments/. A route can include weighing, ball milling, pelletizing, heat treatment, quenching, grinding, and XRD measurement. For an XRD CSV, send multipart form data with both data:write and files:write.

Literature data

Use POST /literature/ for DOI metadata, reported synthesis outcomes, and literature-derived synthesis steps. The DOI helpers can check LOOP mappings and retrieve Crossref metadata.

Computational data and model output

Use POST /computational/ for DFT properties and structured ML prediction payloads. Keep model outputs labelled as predictions until your validation workflow supports stronger claims.

Batch imports

Use POST /imports/ with JSON or JSONL. Start with dry_run=true to validate every row before writing anything.

Responses, errors, and limits

Successful responses return a data envelope. Errors use a consistent problem response with a status code, readable detail, and field errors when validation fails.

  • 401: the key is missing, invalid, expired, or revoked.
  • 403: the account or key lacks the required approval or scope.
  • 422: the submitted record could not be validated.
  • 429: slow down and honor the Retry-After header.

Default limits protect both LOOP and shared resources. The integration guide explains uploads, batch imports, and tested request examples in plain language.
