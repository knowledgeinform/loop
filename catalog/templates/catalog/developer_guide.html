Before you build

LOOP’s API uses the same validation and storage paths as the website’s Add Data screens. An API client does not create a separate catalog: material AUIDs, records, and access rules remain the same.

Base URL: {{ api_base_url }}

1. Make a key

Create one named key per notebook, script, or service. Copy the secret once and put it in an environment variable or secret manager.

2. Start read-only

Use data:read first. Add write scopes only when a tested workflow needs them.

3. Validate before writing

Test one record or run a dry import before committing an entire batch.

Read materials

Start by querying known compositions. This lets you confirm access, learn the response shape, and avoid duplicating data that is already in LOOP.

curl --request GET \
  "{{ materials_url }}?elements=Ti,Zr,O&structure_family=fluorite" \
  --header "X-API-Key: $LOOP_API_KEY"
{{ python_samples.read_materials }}

The response contains a data array and list metadata. Use GET /materials/{material_auid}/ when you already know a material AUID. For every available filter and returned field, open the API Reference.

Every Python example on this page is a single self-contained file with no third-party dependencies and no helper module to fetch: save it, set LOOP_API_KEY and LOOP_API_BASE_URL, and run it. Each is also downloadable on its own — read_materials.py, upload_xrd_experiment.py, and so on.

Page through a result set

List endpoints serve at most 100 rows per request. Advance offset by limit while meta.has_more is true; meta.total counts every match your account may see, before the page window is applied. Do not parallelize the pages aggressively — a 429 carries a Retry-After that is authoritative.

curl --fail-with-body \
  "{{ materials_url }}?structure_family=pyrochlore&limit=100" \
  --header "X-API-Key: $LOOP_API_KEY"

curl --fail-with-body \
  "{{ materials_url }}?structure_family=pyrochlore&limit=100&offset=100" \
  --header "X-API-Key: $LOOP_API_KEY"
{{ python_samples.paginate_materials }}

A mistyped filter is rejected with a 400 rather than ignored, so a page walk never silently returns an unfiltered population. page, cursor, and skip are not supported.

Add experimental data with a synthesis route

An experimental record describes what was done in order. Put each operation in synthesis_steps, from precursor weighing through characterization. This is how a detailed synthesis route—rather than just a final material label—enters LOOP.

Ball milling and heat treatment

Use a ball_milling step for milling time, RPM, ball-to-powder ratio, and atmosphere. Follow it with steps such as pelletizing, heat treatment, annealing, quenching, grinding, or XRD measurement as appropriate to the experiment.

{{ documented_experiment_json }}

Send this JSON to POST /experiments/ with data:write.

Attach the XRD pattern

To store the raw pattern with the trial, send multipart form data: record holds the same JSON and csv_file holds the file. That request needs both data:write and files:write. The script below validates first, uploads, then reads back what LOOP parsed — the full path a synthesis run takes into the catalog.

curl --fail-with-body --request POST "{{ api_base_url }}experiments/" \
  --header "X-API-Key: $LOOP_API_KEY" \
  --form 'record={"elements":{"Gd":2,"Zr":2,"O":7},"structure_family":"pyrochlore","phase_status":"single_phase","raw_data_type":"xrd"}' \
  --form 'csv_file=@pattern.csv;type=text/csv'
{{ python_samples.upload_xrd_experiment }}
Raw data is deduplicated by hash. Uploading a CSV that already exists on another trial is refused with a 409 rather than stored twice, and an identical trial on the same recipe is refused the same way. Treat a 409 as "already recorded", not as a failure to retry.

Read the pattern back

Once stored, a permitted reader can retrieve the original CSV at GET /recipes/{recipe_auid}/trials/{trial_id}/xrd/, the parsed metadata at /xrd/metadata/, or a rendered preview at /xrd/preview/. LOOP keeps the exact bytes you uploaded, so a reanalysis starts from the original file.

curl --fail-with-body --output pattern.csv \
  "{{ api_base_url }}recipes/$RECIPE_AUID/trials/$TRIAL_ID/xrd/" \
  --header "X-API-Key: $LOOP_API_KEY"

curl --fail-with-body \
  "{{ api_base_url }}recipes/$RECIPE_AUID/trials/$TRIAL_ID/xrd/metadata/" \
  --header "X-API-Key: $LOOP_API_KEY"
{{ python_samples.download_xrd }}

Reuse precursors and protocols

These are helpers for building experimental routes; neither is an experimental, literature, or computational result.

LibraryPurposeWebsite useAPI
Saved precursorOne recurring reagent: CAS, name, formula, purity, supplier, and notes.Insert it into a weighing step.GET, POST /precursors/; GET, PATCH, DELETE /precursors/{id}/
Saved protocolAn ordered template of synthesis steps, including precursor snapshots on weighing steps.Load it to replace the current experiment steps, or save the current steps as a template.GET, POST /protocols/; GET, PATCH, DELETE /protocols/{id}/

A saved protocol does not link to a mutable precursor record. It preserves the values selected when the protocol was saved, so later edits to a library precursor do not silently rewrite a historical route. Both libraries are visible to the owner and their shared affiliations; only the uploader can change or delete an entry.

All reusable-library operations require an authenticated key with data:read for reads or data:write for creates and edits. GET /precursors/cas-lookup/?cas=13463-67-7 can prefill a precursor from a CAS number.

Validate and import data safely

Use POST /records/validate/ to normalize one record without storing it. For a collection of records, send JSON or JSONL to POST /imports/ with dry_run=true first. LOOP reports each row independently, so you can correct only the rows that fail before committing.

curl --fail-with-body --request POST "{{ api_base_url }}imports/" \
  --header "X-API-Key: $LOOP_API_KEY" \
  --form 'record_type=experiment' \
  --form 'dry_run=true' \
  --form 'file=@experiments.jsonl;type=application/x-ndjson'
{{ python_samples.batch_import }}

An import of up to 100 records answers 200 for a dry run, 201 when every row was created, 207 when some rows failed, and 422 when none succeeded. Read data[].status per row rather than relying on the status code alone.

Recommended workflow: validate one representative record → run a dry import → review row errors → import the corrected batch. Batch imports require imports:write.

Operate safely

SituationWhat to do
Key is exposed or no longer neededRevoke it from API Keys; create a replacement rather than sharing a key.
401 or 403Check that the key is current, the account is approved, and the requested scope is present.
422Read the field errors in the problem response, correct the record, then validate again.
429Pause and honor the Retry-After header before retrying.

Production use

Use the deployed HTTPS API base URL, verify the health endpoint with an authenticated account, and begin with a short-lived read-only key. LOOP operators manage deployment and data retention separately.
